# UI Library Phase 5–6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export a Tailwind CSS preset so consumer projects can inherit the library's theme tokens (Phase 5), and install + configure Storybook 8 with React-Vite for isolated component development (Phase 6).

**Architecture:** Phase 5 adds `src/tailwind-preset.ts` as a second tsup entry point — tsup bundles it to `dist/tailwind-preset.js` (CJS) and `dist/tailwind-preset.mjs` (ESM) with `tokens.ts` values inlined, then `package.json` exports the path. Phase 6 installs Storybook 8 with `@storybook/react-vite` and wires `globals.css` in `.storybook/preview.ts` so Tailwind CSS variables are active in all stories; the existing `button.stories.tsx` serves as the smoke-test.

**Tech Stack:** tsup (existing), Tailwind CSS v3 (existing), tokens.ts (existing), Storybook 8, @storybook/react-vite, Vite (already present via @vitejs/plugin-react + vitest)

**Spec:** `readme.md` at project root

## Global Constraints

- Package name: `@ui/ui-lib`
- Node ≥18, pnpm (not npm/yarn) for all installs
- React/React-DOM remain `peerDependencies` only — never add them to `dependencies` or `devDependencies`
- All Tailwind classes stay semantic (`bg-primary`, `rounded-md`, etc.) — no arbitrary values
- `dts: false` stays in `tsup.config.ts` (TypeScript 7 removed the DTS API tsup uses) — declarations are generated by `pnpm build:types` (`tsc -p tsconfig.build.json`)
- `sideEffects: ["./dist/style.css"]` must stay in `package.json` — never set `sideEffects: false`
- Every task ends with a `git commit`

### Task 1: Tailwind Preset Export (Phase 5)

**Goal:** `dist/tailwind-preset.js` and `dist/tailwind-preset.mjs` are produced by `pnpm build`, containing the Tailwind theme extension (colours, radius, spacing, fontSize) derived from `tokens.ts`. Consumer projects can do `import uiPreset from '@ui/ui-lib/tailwind-preset'` and pass it to Tailwind's `presets` array.

**Files:**
- Create: `src/tailwind-preset.ts`
- Modify: `tsup.config.ts` — add second entry
- Modify: `package.json` — add `./tailwind-preset` export condition

**Interfaces:**
- Produces: `dist/tailwind-preset.js` (CJS), `dist/tailwind-preset.mjs` (ESM), `dist/tailwind-preset.d.ts` (via `build:types`)
- Consumes: `src/tokens/tokens.ts` (spacing, fontSize, radius values)
- No tests required — verified by `pnpm build` succeeding and a Node.js smoke test

- [ ] **Step 1: Write `src/tailwind-preset.ts`**

The preset must NOT include a `content` array — that is the consumer's responsibility. It mirrors the `theme.extend` block from `tailwind.config.ts` exactly so both the lib's internal Tailwind compile and the consumer's compile produce consistent utility classes.

```ts
// src/tailwind-preset.ts
import { tokens } from './tokens/tokens'

const preset = {
  darkMode: 'class' as const,
  theme: {
    extend: {
      colors: {
        background: 'hsl(var(--background))',
        foreground: 'hsl(var(--foreground))',
        primary: {
          DEFAULT: 'hsl(var(--primary))',
          foreground: 'hsl(var(--primary-foreground))',
        },
        secondary: {
          DEFAULT: 'hsl(var(--secondary))',
          foreground: 'hsl(var(--secondary-foreground))',
        },
        destructive: {
          DEFAULT: 'hsl(var(--destructive))',
          foreground: 'hsl(var(--destructive-foreground))',
        },
        muted: {
          DEFAULT: 'hsl(var(--muted))',
          foreground: 'hsl(var(--muted-foreground))',
        },
        accent: {
          DEFAULT: 'hsl(var(--accent))',
          foreground: 'hsl(var(--accent-foreground))',
        },
        popover: {
          DEFAULT: 'hsl(var(--popover))',
          foreground: 'hsl(var(--popover-foreground))',
        },
        card: {
          DEFAULT: 'hsl(var(--card))',
          foreground: 'hsl(var(--card-foreground))',
        },
        border: 'hsl(var(--border))',
        input: 'hsl(var(--input))',
        ring: 'hsl(var(--ring))',
      },
      borderRadius: {
        sm: 'calc(var(--radius) - 4px)',
        md: 'calc(var(--radius) - 2px)',
        lg: 'var(--radius)',
        xl: 'calc(var(--radius) + 4px)',
        full: tokens.radius.full,
      },
      spacing: tokens.spacing as Record<string, string>,
      fontSize: tokens.typography.fontSize as Record<string, string>,
    },
  },
}

export default preset
```

- [ ] **Step 2: Verify TypeScript accepts the file**

```bash
pnpm exec tsc --noEmit
```

Expected: exits with no errors. If `as Record<string, string>` causes a type conflict, remove the casts — Tailwind's theme types accept loose shapes.

- [ ] **Step 3: Update `tsup.config.ts` — add second entry**

Read `tsup.config.ts` first. Change:
```ts
entry: ['src/index.ts'],
```
to:
```ts
entry: ['src/index.ts', 'src/tailwind-preset.ts'],
```

All other options remain unchanged (`dts: false`, `clean: true`, etc.).

- [ ] **Step 4: Update `package.json` — add `./tailwind-preset` export**

Read `package.json` first. After the `"./style.css"` entry in `exports`, add:

```json
"./tailwind-preset": {
  "types": "./dist/tailwind-preset.d.ts",
  "import": "./dist/tailwind-preset.mjs",
  "require": "./dist/tailwind-preset.js"
}
```

`"types"` must be first in the condition object (TypeScript `node16` resolution requires this). The `files: ["dist"]` field already covers the new output files — no change needed.

**Note on CJS interop:** tsup wraps `export default` in CJS as `{ default: preset, __esModule: true }`. Modern ESM consumers (`import preset from '@ui/ui-lib/tailwind-preset'`) get the default correctly. Raw CJS consumers (`require(...)`) need `.default`: `presets: [require('@ui/ui-lib/tailwind-preset').default]`. TypeScript-based Tailwind configs (most modern projects) use ESM and are not affected.

- [ ] **Step 5: Run `pnpm build` and verify outputs**

```bash
pnpm build
```

Expected files in `dist/` after build:
- `tailwind-preset.js` — CJS bundle
- `tailwind-preset.mjs` — ESM bundle
- `tailwind-preset.d.ts` — TypeScript declaration (from `build:types`)

If `tailwind-preset.d.ts` is absent but the others exist, it means `tsconfig.build.json` didn't pick up the file. Verify `tsconfig.build.json` has `"include": ["src"]` — `src/tailwind-preset.ts` is under `src/` so it should be covered. Re-run `pnpm build:types` in isolation to confirm.

- [ ] **Step 6: Smoke-test the CJS output**

```bash
node -e "
  const m = require('./dist/tailwind-preset.js');
  const p = m.default ?? m;
  console.log('darkMode:', p.darkMode);
  console.log('color keys:', Object.keys(p.theme.extend.colors).join(', '));
  console.log('spacing keys:', Object.keys(p.theme.extend.spacing).join(', '));
  process.exit(0);
"
```

Expected output:
```
darkMode: class
color keys: background, foreground, primary, secondary, destructive, muted, accent, popover, card, border, input, ring
spacing keys: xs, sm, md, lg, xl
```

- [ ] **Step 7: Commit**

```bash
git add src/tailwind-preset.ts tsup.config.ts package.json
git commit -m "feat: tailwind-preset export for consumer theme inheritance (Phase 5)"
```

### Task 2: Storybook 8 Setup (Phase 6)

**Goal:** Storybook 8 with `@storybook/react-vite` is installed and configured. Running `pnpm storybook` starts the dev server; `pnpm build:storybook` produces `storybook-static/` without errors. The existing `src/components/button/button.stories.tsx` renders correctly with the library's Tailwind theme (colours from CSS variables visible).

**Files:**
- Create: `.storybook/main.ts`
- Create: `.storybook/preview.ts`
- Modify: `package.json` — add `storybook` and `build:storybook` scripts
- Modify: `.gitignore` — add `storybook-static/`
- Modify: `tsconfig.json` — add `.storybook` to exclude

**Interfaces:**
- Consumes: `src/styles/globals.css` (imported in preview.ts — injects Tailwind utilities + CSS variable tokens into all stories)
- Consumes: `src/components/button/button.stories.tsx` (existing — 6 stories, already excluded from `tsc` via `**/*.stories.tsx`)
- Consumes: `postcss.config.js` + `tailwind.config.ts` (Vite picks both up automatically for CSS processing)

- [ ] **Step 1: Install Storybook 8 packages**

```bash
pnpm add -D storybook@^8 @storybook/react@^8 @storybook/react-vite@^8 @storybook/addon-essentials@^8
```

Do NOT install `react` or `react-dom` here — they are peerDependencies only.

If pnpm v11 blocks a native build during install (security policy error), add the blocked package name to `pnpm-workspace.yaml` under `allowBuilds:` on its own line:
```yaml
allowBuilds:
  esbuild: true
  <blocked-package>: true
```

If the install is very slow due to many optional native packages, that is normal for Storybook — wait for it to complete.

- [ ] **Step 2: Create `.storybook/main.ts`**

```ts
import type { StorybookConfig } from '@storybook/react-vite'

const config: StorybookConfig = {
  stories: ['../src/**/*.stories.@(js|jsx|ts|tsx)'],
  addons: ['@storybook/addon-essentials'],
  framework: {
    name: '@storybook/react-vite',
    options: {},
  },
}

export default config
```

- [ ] **Step 3: Create `.storybook/preview.ts`**

```ts
import '../src/styles/globals.css'
import type { Preview } from '@storybook/react'

const preview: Preview = {
  parameters: {
    controls: {
      matchers: {
        color: /(background|color)$/i,
        date: /Date$/i,
      },
    },
  },
}

export default preview
```

The import `'../src/styles/globals.css'` is relative to `.storybook/` — correct path. Vite processes this CSS through PostCSS/Tailwind automatically because `postcss.config.js` and `tailwind.config.ts` are at the project root.

- [ ] **Step 4: Update `package.json` scripts**

Read `package.json` first. Add to the `scripts` object (after `"lint"`):
```json
"storybook": "storybook dev -p 6006",
"build:storybook": "storybook build"
```

Keep `"dev": "tsup --watch"` unchanged — tsup watch is the lib's build dev mode; Storybook has its own named script.

- [ ] **Step 5: Update `.gitignore`**

Read `.gitignore` first. Add `storybook-static/` on its own line after `dist/`:
```
storybook-static/
```

- [ ] **Step 6: Update `tsconfig.json` — exclude `.storybook/`**

Read `tsconfig.json` first. The current `exclude` array is:
```json
"exclude": ["node_modules", "dist", "**/*.stories.tsx"]
```

Change to:
```json
"exclude": ["node_modules", "dist", "**/*.stories.tsx", ".storybook"]
```

This prevents `tsc` from erroring on Storybook's own TypeScript config files when running `pnpm build:types`.

- [ ] **Step 7: Verify Storybook builds without fatal errors**

Run a static build (no interactive server needed):
```bash
pnpm build:storybook 2>&1 | tail -30
```

Expected: last line contains something like `=> Output directory: storybook-static` with no `ERROR` or uncaught exception lines. Peer-dependency warnings are OK; a missing `@storybook/react` import would be a fatal error (resolved by the install in Step 1).

**If build fails with "Cannot find module '@storybook/react-vite'"** — pnpm hoisting issue. Add to `.npmrc`:
```
public-hoist-pattern[]=*storybook*
```
Then re-run `pnpm install` followed by `pnpm build:storybook`.

**If build fails with a PostCSS/Tailwind error on `globals.css`** — verify `postcss.config.js` exists at the project root and `tailwindcss` is in `devDependencies`. Both should already be in place from Phase 2.

**If build fails with "Cannot find module '../src/styles/globals.css'"** — verify the path in `preview.ts` is `'../src/styles/globals.css'` (two directories up from `.storybook/`).

- [ ] **Step 8: Run the full test suite to confirm nothing regressed**

```bash
pnpm test:run
```

Expected: 10 tests pass. The Storybook changes touch no source files and should not affect tests.

- [ ] **Step 9: Commit**

```bash
git add .storybook/ package.json pnpm-lock.yaml .gitignore tsconfig.json pnpm-workspace.yaml
git commit -m "feat: Storybook 8 + React-Vite setup, preview imports globals.css (Phase 6)"
```
